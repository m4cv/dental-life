# Architecture

One rule: every game system lives in its own folder under `src/` and talks to the rest through
small, typed interfaces. Folders marked *(empty)* hold only a `.gitkeep` until their stage.

## Rendering flow

```
main.tsx → App ──(screen = menu)──▶ MainMenu
              └─(screen = game)──▶ [WebGL2 ok?] ─▶ lazy GameScreen
                                                    ├─ GameCanvas (R3F <Canvas>, graphics profile)
                                                    │    ├─ <PlayableScene /> (world/): lights, backdrop, <PlayerRig> (character + follow camera)
                                                    │    │    (with ?preview=1: <CharacterShowcase /> instead)
                                                    │    └─ <FpsMeter />
                                                    └─ HUD overlay (DOM): TouchControls, Menu button, Diagnostics
                                                         (with ?preview=1: CharacterPreviewPanel instead of TouchControls)
```

* 3D lives inside `<GameCanvas>`; HUD / menus are ordinary DOM on top of it.
* Per-frame values never go through React state. FPS is the one exception and is throttled to 2 Hz.
* Performance knobs (pixel-ratio cap, shadows, MSAA) are in `config/graphics.ts`.

## Assets

* `reference/photos/**` — the original photographs. Read-only, and kept local (git-ignored: the GitHub repository is public). `reference/MANIFEST.sha256` lets
  anyone verify they are unchanged: `cd reference/photos && sha256sum -c ../MANIFEST.sha256`.
* `public/assets/<category>/` — anything generated or modelled for the game (GLB, textures,
  audio), loaded lazily at runtime. Categories: character, car, home, streets, university,
  clinic, npcs, environment, audio, ui.
* Where a photo cannot be turned into an accurate model, the stage will build a simplified
  hand-modelled approximation and say so explicitly.

## Dependencies deliberately not added yet
* **react-router-dom** — the menu ↔ game switch is a single store value; routes arrive when
  there are enough real screens to justify them.
* **@dimforge/rapier3d-compat** — physics arrives with character collision (Stage 2/3) or
  driving (Stage 6), whichever needs it first.
* IndexedDB / LocalStorage — Stage 13 (save system).

## Character (Stage 2)

* **No model file.** The player is built from primitives and procedural meshes, and posed every
  frame from code, so nothing is downloaded and the look is tunable. Heights are metres, +z forward,
  +x the character's left. Standing ankle height = hip − thigh − shin (`RIG` in `animations/pose.ts`).
* `animations/pose.ts` — pure maths (no three.js): `solvePose(pose, speed, phase, time)` blends idle →
  walk → run from a speed in m/s, solves foot contact so feet never sink below the ground, and adds
  blinking and breathing. `advancePhase` advances the gait cycle.
* `charShapes.ts` — pure shape data (coat rings, hijab shell/drape, decals, strap). `assets.ts` turns
  it into three.js geometry/materials once and shares them. `PlayerCharacter.tsx` assembles the rig.
* **Face:** the eyes are 3D (eyeball, textured iris cap, glints, a morph-driven eyelid that rests over the
  top of the iris and closes on blink, tapered eyeliner). Blush, eyeshadow, brows and lips are painted on a thin
  skin-shaped sheet (`facePatchMesh` + `faceTexture` in `assets.ts`). Eye and face proportions are in `charShapes.ts` (`EYE`, `FACE_PATCH`).
* The controller drives it with `<PlayerCharacter speed={…} position={…} rotationY={…} />`; `speed` may be a number or a `{ current }` ref so the rig can update it every frame without re-rendering.
* `npm test` runs `scripts/test-pose.mjs`, `scripts/test-shapes.mjs` and `scripts/test-controls.mjs` on plain Node.
* The coat is two pieces (torso and a hem that swings with the hips). Each continues a few centimetres past their seam, a little smaller (`tuckCoatMesh`), so the hem can tilt while running without showing a hole.
* Colours come from the reference photos; **trousers and shoes are not visible in them** and are a
  neutral choice.

## Controls (Stage 3)

* **Conventions.** The ground plane is (x, z). The camera yaw is the compass heading: forward = (sin yaw, cos yaw), right = (−cos yaw, sin yaw). Stick input is x = right, y = forward, and is turned into a world direction relative to the camera (`stickToWorld`). The character's `heading` is a rotation about +y.
* **Input is not React state.** `controls/input.ts` is a mutable object written by pointer / key events and read once per frame, so touching the screen never re-renders anything. The Run toggle is the one Zustand value because the button has to light up.
* **One frame loop.** `PlayerRig` has the only `useFrame`, so the order is fixed: look / recentre → `stepPlayer` → move the character → move the sun (its shadow box follows her) → spring-arm camera → throttled read-out.
* **Movement** (`controls/movement.ts`, pure and unit-tested). Dead-zone 0.12 with a smooth ramp, acceleration 9 and braking 14 m/s², the character turns toward her motion at up to 12 rad/s, walk 1.45 / run 3.6 m/s. Time is sub-stepped at 1/30 s and one frame is capped at 0.5 s, so slow phones move at the same real speed as fast ones. Speed is measured from the actual displacement after collisions, so pushing into a wall brings the walk animation to a stop.
* **Collision.** Axis-aligned boxes and circles with a height, a 0.28 m player radius, iterative push-out (slides along walls) and a world boundary. The courtyard's colliders live in `world/courtyardLayout.ts`; later stages add their own lists. Rapier is still deliberately not used.
* **Camera** (`camera/followCamera.ts`). Orbit around a pivot 1.45 m above the ground: default pitch 0.26 rad (−0.05 … 1.15), distance 4.6 m (2.2 … 9). The spring-arm marches from the pivot outwards and stops at a tall collider or just above the floor; the arm shortens instantly and lengthens smoothly. Dragging works like turning your head: right turns the view to the right, left to the left, down looks down (the camera rises), spreading two fingers zooms in.
* **Landscape first.** The game is designed for a phone held sideways. `controls/layout.ts` sizes the controls from the *short* side of the screen: joystick base = 31 % of it (96–150 px, so 121 px on an 844×390 phone), Run 17 % (56–72 px), Recentre 78 % of Run (48–56 px). Run sits in the bottom-right corner with Recentre stacked above it; the joystick rests in the bottom-left corner. Left/right safe-area insets keep controls off a notch. `ui/components/RotatePrompt.tsx` covers the game while the screen is narrow portrait (`needsRotate`: height > width and width < 820 px), so tablets and desktop windows are left alone. The Stage 2 inspector (`?preview=1`) has no prompt.
* **Full screen + lock.** `engine/orientation.ts`, called from the New Game tap on touch devices only (`pointer: coarse`): `requestFullscreen` then `screen.orientation.lock('landscape')`. Both are allowed to fail silently (iPhone Safari refuses both); the rotate prompt covers that case. The camera's vertical field of view is 46° on wide screens and 50° on tall ones (`fovForAspect`).
* **Touch UI** (`controls/TouchControls.tsx`). Pointer events on one full-screen layer with `touch-action: none`. The floating joystick appears wherever the left thumb lands (left half of the screen); the right half looks, and two fingers on the right half pinch. The buttons stay out of the stick's way and are excluded from the look drag. Rotating the phone lets go of any touch and re-seats the resting joystick. A hint pill fades after 9 s or the first touch.
* **Testing.** `scripts/test-controls.mjs` (about 60 checks, including layout sizes and the rotate rule: shaping, camera-relative direction, acceleration, turning, frame-rate independence at 120 / 60 / 20 FPS, collisions, camera rig). `scripts/smoke-test.mjs` drives the real page at 844×390 landscape with synthetic multi-touch (CDP `Input.dispatchTouchEvent`) in headless Chrome and checks the menu fit, control placement (no overlaps), the portrait prompt and rotating back, walking, running, wall collision, camera drag, recentre, pinch zoom, no page scroll, keyboard fallback and new-game reset.
* **Preview.** `?preview=1` opens the Stage 2 character inspector instead of the playable scene.

## The home (Stage 4)

* **One layout, two readers.** `home/homeLayout.ts` is plain data and pure functions (no three.js, no React). The scene draws it and the movement code collides with it, so what you see and what stops you cannot drift apart. Walls are generated from centre lines (0.2 m thick, 2.9 m high); doors, windows and openings are cut into them (`wallPieces`). A window stays solid for the player, a door is a gap. Furniture has a collision footprint that is separate from its detailed look.
* **Estimated, not measured.** Room sizes, door positions and the bathroom are estimates from five photographs; each room is marked `photos` or `estimate` in `ROOMS`. Replace the numbers when a plan exists and everything follows.
* **Cheap to draw.** `home/sceneBuilder.ts` collects boxes, cylinders, spheres, rings and planes and merges them into one mesh per material, so the whole home is a few dozen draw calls. Textures (the lace-pattern floor tile, black marble, wood grain, the sage-green quilt, the television picture) are drawn on small canvases at start-up; there are no image downloads. Only the front-door leaf and the pink notebook are separate meshes because they move. Three warm point lights (chandelier, bedside lamp, dining pendant), a hemisphere light and a mostly overhead sun that only gives soft shadows indoors.
* **Doing things.** `world/HomeScene.tsx` gives `PlayerRig` a list of spots. When she stands inside a spot's reach and the step is not done, `PlayerRig` publishes a prompt (`usePromptStore`) and the **Interact** button (or E) appears. Tapping it starts an action (`controls/interaction.ts`): the stick is locked, she is walked to the exact spot through the normal collision code (2 s limit), turns to face the right way and plays a gesture (`character/animations/pose.ts` → `applyGesture`: brush, mirror, dress, eat, pack, open) for 1.6–3.2 s. When it ends, `useRoutineStore.finish` ticks the step, moves the clock on (06:30 → 07:00) and shows a message. The front door's collider is removed and the door swings open only once all five steps are done.
* **Indoor camera.** `PlayerRig` runs the camera in indoor mode when a ceiling height is given: the arm may come as close as 0.5 m, keeps 0.18 m from walls, stays under the ceiling, and when the way back is short it climbs and looks down from above (`indoorPitch`, up to 83° in a tight spot) instead of ending up behind a wall. Ceiling fixtures and wall air-conditioners are *camera-only* colliders (`CAMERA_ONLY_COLLIDERS`, with a `bottom` height): she walks under them, the camera stays out of them. `test-controls.mjs` checks every free position in every room at eight headings (never behind a wall, inside furniture or a fixture, above the ceiling, or closer than 0.8 m).
* **Testing.** `scripts/test-home.mjs` (58 checks): wall splitting, windows vs doors, a 10 cm flood fill with the real player radius proving every spot and room is reachable with the door shut (also with a fatter 0.36 m body, so thumbs do not have to be exact), the door and porch pen, spot logic, the routine, 64 simulated actions with the real movement code, the `?at=` parser. `test-pose.mjs` covers the gestures, `test-controls.mjs` the ceiling and the indoor camera. `scripts/smoke-test.mjs` drives the real page in headless Chrome: Stage 3 against `?scene=courtyard`, then Stage 4 — steering the on-screen stick from the read-out it walks bedroom → living room → dining → bathroom, presses Interact at each spot, checks the checklist, clock, locked stick, the greyed-out and shut front door, then the open door and the porch, and finally one picture per room.

## The neighbourhood (Stage 5)

* **One world, no loading.** `world/NeighbourhoodScene.tsx` puts the Stage 4 home and the new street in one scene. The home keeps its coordinates (front door at x 2.5, z 0.1 on the south wall); the street is built around it. `PlayerRig` takes a function for the ceiling (`insideHome(x, z)`) and for the sun, so inside the house the tight-space camera and the overhead sun of Stage 4 apply, and outside the camera uses the same tight-space logic with no ceiling (it rises to a bird's-eye view when a wall is behind her) and the sun becomes a low morning sun from the east. The switch is eased, so nothing jumps at the doorway.
* **One layout, two readers (again).** `street/streetLayout.ts` is pure data and functions. Roads are rectangles that do not overlap (so nothing flickers where they meet); buildings come from *rows* of lots along the roads, split into varied widths with a fixed-seed random generator (`mulberry32(90)`), so the street is always the same and the tests can check it. Every lot is a solid block from the street line back, with a height of ground floor + 3.2 m per further floor. The walls of the yard, the lamps, palms, bins and the barriers all appear both as drawn things and as colliders.
* **Cheap to draw.** `buildStreet.ts` merges everything into about fifty meshes (one per material). Building walls repeat one small canvas texture per bay (`Batch.facadeBox` rounds to whole bays, so windows are never cut): 14 window styles (7 paint colours × sliding or shuttered), 7 lane ground floors with a door, 5 shopfronts for Ninety Street. Rooftop water tanks, stair rooms, parapets, a pedestrian crossing and lane markings are boxes. No image downloads.
* **Fast collisions.** `controls/spatial.ts` puts the colliders in a 12 m grid. Movement asks for the colliders within 2 m of the cell she stands in, the camera for those within 10.5 m, so the 130-odd colliders of the street cost a handful of tests per frame. There is one grid per state of the front door.
* **Where she is.** `zoneAt(x, z)` gives `home`, `yard`, `lane` or `boulevard`; the HUD's place chip shows the name.
* **Estimated, not measured.** The only outdoor references are satellite screenshots of Ninety Street. The home's position on the map, lane widths (6 m), the yard (10.6 × 15.2 m with a 2 m gate), building sizes and the barriers' positions are estimates. Everything is data in `streetLayout.ts`; moving the home or the road is a data edit.
* **Testing.** `scripts/test-street.mjs` (about 90 checks): no overlaps between buildings, roads, plot and house; every building faces a road; the roof parapet closes around the house; a 25 cm flood fill with the real player radius proving the whole neighbourhood is reachable from the porch (both ends of every lane, both pavements, the median, the yard all round the house) and the inside of buildings and the far side of the barriers are not; with the door shut she cannot leave; a 1.2 m wide walker still gets through the gate and along every lane; the collider grid never drops a collider within reach; the camera never ends up inside a building or wall (about 11,000 position × heading cases). `scripts/smoke-test.mjs` runs Stage 3 on `?scene=courtyard`, Stage 4 on `?scene=home`, and now Stage 5 on the default scene: from the porch she walks through the gate, down the lane (place chip changes), runs to Ninety Street, crosses it, and is stopped by the shops, the buildings and the barrier; then walks back in through the open front door; then one picture from each of eight places.

## The car (Stage 6)

* **Where it lives.** `src/vehicle/`: `carPhysics.ts` (pure, no three.js), `carLayout.ts` (where it is parked and the `?car=` / `?drive=1` query parsing) and `buildCar.ts` (the model). `PlayerRig` stays the single per-frame loop: it holds the car's state, and while she sits in it the car takes the character's place for movement, camera, sun and read-out. `state/useDriveStore.ts` carries only what the HUD needs (driving, km/h, gear).
* **Physics.** A bicycle model integrated at the rear axle (wheelbase 2.4 m, 3.65 × 1.62 m body). Throttle and one brake pedal (which reverses once the car has stopped), rolling resistance and quadratic drag, a steering angle that eases toward the stick and is limited by speed so that lateral acceleration never exceeds 7 m/s² (it cannot flip or spin). Top speed 13 m/s (47 km/h), reverse 3.5 m/s. Stepping is done in 1/60 s sub-steps with a cap of 0.5 s per frame, so a slow phone cannot tunnel through a wall.
* **Collisions.** Four circles (offsets −1, −0.33, 0.33, 1 m along the car, radius 0.84) are pushed out of the colliders; a head-on hit stops the car, a graze swings the nose along the obstacle instead of killing the speed. The car uses a wider collider grid (reach 3.2 m) than the walker (2 m), one per state of the front door. A person cannot walk through a parked car (`carColliders`, circles of 0.8 m).
* **Getting in and out.** The prompt `Get in car` shows within 1.35 m of the body. `Get out` is enabled below 1.2 m/s; she steps out on the driver's side, else the other side, else the rear or front, and if none is free the button explains that there is no room.
* **Controls.** `input.gas`, `input.brake` and `readDrive()` in `controls/input.ts` (stick x steers with a dead zone and a mild curve; the keyboard gives the same). The touch pedals are `data-touch-button`s that hold while the finger is down, so the left thumb can steer at the same time. Pedal sizes are in `controls/layout.ts`.
* **Camera.** The chase camera sits 6.2 m behind and a little above the car, swings in behind it while it moves (not for 1.8 s after a manual drag), and widens the field of view by up to 6° with speed. The same spring-arm keeps it out of walls.
* **Model.** Merged per material, like the street; the body is an extruded side silhouette with wheel arches, glass, lamps (the tail lights brighten when braking, the reverse lamps when backing up), mirrors, handles, blank number plates, wheels that spin with the distance driven and the front pair that turn, and the body leans with acceleration and cornering. A simplified seated figure is shown in the driver's seat while she drives.
* **Testing.** `scripts/test-car.mjs` (41 checks, plain Node): pedals, reverse, steering sign, the turning circle, the lateral-acceleration cap, collisions with walls, lamps and the edge of the world (a car at top speed cannot pass a 25 cm wall at any frame rate from 120 to 2 per second), grazing, the enter and exit rules, query parsing, and drives through the real neighbourhood (down the lane and across Ninety Street to the shops, the whole length of the street to the barrier, a three-point turn in the 6 m lane, the car stopped by the house wall). `scripts/smoke-test.mjs` adds a browser drive: Get in car, Gas, steering, the wall, Brake and reverse, Get out, then `?drive=1` runs east across Ninety Street and north to the barrier.
* **Limits.** No traffic, people or sound; there are no kerbs, so the car can drive on the pavements; the driver is a simplified figure; the parking place and the car's colours are estimates; the clock does not advance while driving (Stage 7 adds the route and the time).

## The route (Stage 7)

* **What it adds.** Ninety Street, which Stage 5 closed with a barrier at z −30, goes on north for 330 m (z −70 to −405) between rows of shops with six 7 m side streets (each ends in a blind block), into a 30 × 30 m paved **roundabout** (island radius 7.5 m, a 7 m ring road) whose north and east exits are closed by buildings. Its third exit leads **west along Al-Shaab Street** (16 m of asphalt, 3 m pavements, 290 m long, rows of buildings on both sides, closed at its west end). On the north side, between x −200 and −120, stands the **university's walled compound**: a 9 m gate with two pillars carrying an English and Arabic sign, a guard booth, a forecourt with a tan canopy over parking bays, palms and lamps, and at the back the cream stone main building (4 floors of 4.2 m, 44 m wide, arched windows, two 2-floor wings, a projecting entrance 16 m wide and 4 m deep with blue shoulders, three steps and a red carpet, blue banners). The door is closed; Stage 8 opens it.
* **One layout, two readers (a third time).** `streets/routeLayout.ts` is pure data and functions (no three.js), shared by the scene and the physics. The rows are split with a fixed seed (`mulberry32(2024)`) and the Stage 5 `splitRow`; `WORLD_COLLIDERS = HOME + STREET + ROUTE` (about 330 colliders) is kept in the same 12 m grids over `ROUTE_BOUNDS` (x −256…124, z −500…33.2). The Stage 5 `WORLD_BOUNDS` stays as it was for the Stage 5 tests; `BARRIERS` now has only the south barrier.
* **Chunks.** The route is about 380 × 430 m, so `buildRoute.ts` builds in 110 m squares, each with its own merged meshes and bounding spheres: three.js skips what is behind her or hidden by the fog instead of drawing the whole route every frame. The ground sheet (sand) is one big plane under everything.
* **The drive.** `ROUTE` is a polyline from the home's gate to the forecourt (about 794 m): along the lane, across the median through the gap between a lamp and a palm, north in the middle lane of the east carriageway (right-hand traffic), counter-clockwise round the island, west in the north lane of Al-Shaab Street, then a right turn through the gate. `projectOnRoute` gives where she is along it and how far off; `instructionAt` gives the next instruction; `arrowDegrees` gives the arrow's angle from the camera yaw (`atan2(d·right, d·forward)` for the point 22 m further along the route). `ui/components/RouteHud.tsx` shows distance, arrow and instruction once the front door is open, and an "arrived" card at the end.
* **The clock.** The route is compressed, so time goes by distance: `CLOCK_MIN_PER_M = 0.024` game minutes per metre, on foot or by car, once she has left the yard (`minutesFor`). `PlayerRig` counts the metres the active body moves (teleports and getting in and out do not count) and reports them four times a second through `RigConfig.onTravel`; `NeighbourhoodScene` turns them into minutes (`useRoutineStore.advance`, only with the front door open) and detects arrival (`atUniversity`: inside the compound's wall).
* **Estimated, not measured.** The real university stands on Al-Shaab Street east of Inma City in Aden; where the home is relative to it, the real length of the drive, the roundabout and everything between are estimates. All of it is data in `routeLayout.ts`.
* **Testing.** `scripts/test-route.mjs` (about 90 checks, plain Node): no overlaps between lots, roads, props and the compound, the route lies on roads and keeps 2 m from every solid thing, a 50 cm flood fill with the real player radius proving every part of the route is reachable on foot from the porch (both ends of Al-Shaab Street, every side street, the forecourt, the foot of the steps) and that the inside of buildings, the space behind the rows and the island are not, the arrow's angle for several headings, the zones, the clock, and the **whole drive simulated with the real car physics** by `scripts/route-pilot.mjs` (a pure-pursuit pilot that slows before bends; also with a read-out 0.9 s old, which is what the browser test on a slow machine sees): it arrives without touching anything. `scripts/sim-route.mjs` prints that drive second by second. `scripts/smoke-test.mjs` adds the browser side: north on Ninety Street with the clock and the arrow, the roundabout, Al-Shaab Street, through the gate, the arrival card, the forecourt and the closed entrance, with a contact sheet.
* **Limits.** No traffic, pedestrians or sound; no kerbs, so the car can drive on pavements; no parked cars or people at the university yet; the front door of the main building does not open (Stage 8); one fixed route (the lanes and side streets are open but lead nowhere).

## The university (Stage 8)

* **What it adds.** The main entrance opens. The old solid block is replaced by a **hollow ground floor** (44 × 12 m, 3.6 m clear height, floor 45 cm above the forecourt) under three closed upper floors. Up three 15 cm steps on the red carpet, through the 5 m doorway between the blue shoulders (4 m deep), she is in the **lobby** (granite floor, a guard, two benches, two planters). A 6 m arch leads to the **corridor** (tiles, a row of ceiling lights) with doors to **Lecture Hall 1** (1.4 m doors ×2; three rows of desk blocks with 7 chairs each, a lectern, a whiteboard, the lecturer and four students), **Lecture Hall 2** (smaller), the **Student Affairs office** (1 m door; two desks, cabinets, a clerk) and at the back a 3.2 m door to the **courtyard** (44 × 37 m, paved, two lawns inside hedges, eight blue benches along the wings, two canopied kiosks with tables and stools, a 7.4 m date palm in a planter, two bins). Eighteen simplified people (seven looks, standing or sitting) are placed by hand and do not move.
* **One layout, two readers (a fourth time).** `university/uniLayout.ts` is pure data and functions: every wall is a record with its doorways, and `wallPieces` splits it into solid blocks, lintels and sills, which both the 3D builder and the colliders use, so a doorway can never be drawn where it is solid. The route's `routeLayout.ts` re-exports it, so the world stays one set of colliders in the same 12 m grids (`ROUTE_BOUNDS` now reaches z −552).
* **A raised floor.** Until now the world was flat. `RigConfig.groundAt(x, z)` gives the floor height under her (`floorHeightAt`: 0 in the forecourt, 0.15 / 0.30 / 0.45 on the three treads, 0.45 in the building and the courtyard); `PlayerRig` eases her feet to it (a step is a small climb, not a jump; a jump of more than a metre, such as a teleport, is immediate) and the camera pivot and the shadow follow her height. The car stays at ground level and cannot climb the steps (`ROUTE_CAR_COLLIDERS`). The walking physics is still flat (it ignores height), so steps need no special collision: they are just floor.
* **Under a ceiling.** While she is under the ground-floor ceiling (`insideBuilding`: the main building and the doorway) the camera uses the Stage 4 tight-space rule with `ceilingY = CEIL_Y` (4.05 m), so it never goes through the roof; the upper floors and the entrance's top block are camera-only colliders that start above the ceiling (`bottom`), so the camera does not hit them from below. The sun gets the indoor setting there and one point light follows her, fading in and out (`RigConfig.onFrame`).
* **Where she is.** `campusZoneAt` names the room (`lobby` also covers the doorway). The first time she is through the doorway (`enteredBuilding`) `useRouteStore.enter` stores the time, the route card goes away and a message welcomes her. Standing people, and people seated on their own chair (the guard, the clerk, the kiosk stools), are small solid circles; students at desks are part of the desk block.
* **Estimated, not measured.** There are **no photographs of the inside**: the rooms, their sizes, doors, furniture, the people and the courtyard layout are estimates (the front, the canopy, the sign and the courtyard's character come from the photographs). The whole building is data in `uniLayout.ts` and can be rebuilt from real photographs without touching the code.
* **Testing.** `scripts/test-campus.mjs` (about 70 checks, plain Node): wall and doorway geometry, rooms and furniture without overlaps, the floor height along the steps (never more than 15 cm at a time), the place chip, a 10 cm flood fill from the arrival spot proving every room, the courtyard and the foot of the palm can be reached and the wings, the back wing, the tower and the space behind the walls cannot, that every free cell in the building can be walked to, the camera (about 19 000 positions × 12 headings: never inside a wall, a desk or the upper floors, never above the ceiling, never closer than 0.8 m), the people, and the car. `scripts/smoke-test.mjs` adds the browser side: up the steps (foot height 0 → 0.45), through the doorway, the route card going away, the lobby, the corridor, Lecture Hall 1 with its desks, the office, the courtyard and the planter, with a contact sheet.
* **Limits.** The upper floors, the stairs and the ground floors of the two wings and the back wing are closed blocks; nothing can be interacted with and nobody talks or moves (Stage 9 adds the timetable and Stages 8–12 the people); the doors are open gaps (no door leaves); the signs' Arabic text depends on the device's fonts; the frame rate on a real phone has not been measured.

## Academic life (Stage 9)

* **What it adds.** The real timetable of the fourth level, Group B, as data (`academics/timetable.ts`); a **day of the week chosen at New Game** (menu chips, `?day=`); lectures attended by **sitting at her seat** in the Grand Hall or Hall 313; the **clock running to the end of the lecture**; **present / late / door shut** rules; a timetable panel (🗓 button) and a card that **guides her to the next lecture hall**. Clinic and lab sessions are in the data and the panel but are not playable until Stages 10–11.
* **Pure rules, thin wiring.** `attendance.ts` holds every rule (`lectureState`, `markFor`, `seatOffer`, `beginLecture`, `lectureClock`, `finishLecture`), `guide.ts` the route, `timetable.ts` the data; `useAcademicStore` and `world/campusInteraction.ts` only connect them to the rig. To change a time, a doctor or a place, change a row of `SESSIONS` and nothing else.
* **The seat.** `LECTURE_SEATS` in `uniLayout.ts`: the chair at the aisle end of the first desk row of each hall. A desk row's collider is now split into the table half and the chair half, and the chair half leaves her slot open (`furnColliders`), so she can walk in from the aisle or the back aisle and the rest of the row still blocks. The two seats are two more `Spot`s next to the home's (`homeLayout.ts` `SeatId`), so they use the same walk-to-the-spot-and-act loop; `RigInteraction` gained `onStart` and `onProgress` (the lecture moves the clock as the bar fills, 2 % steps).
* **The sitting pose.** A seventh gesture, `sit`, in `animations/pose.ts`: unlike the standing gestures it also bends both legs (thigh 1.35 rad, knee 1.35 rad, feet flat), lowers the body so the ankles stay on the floor (hips 0.54 m up, on a 0.475 m seat), puts both forearms on the desk and lifts the coat's hem. It blends in and out with the same weight as the other gestures, so sitting down and standing up are smooth.
* **Rules.** Present if she sits down up to 10 minutes after the start, late up to 30, the door is shut after that; a lecture she did not attend is *missed* once it is over. A seat offers the first lecture of its hall that she can still attend (she waits if it has not started). A lecture takes 5 to 18 real seconds whatever its length.
* **The guide.** `guideToSeat(x, z, room)`: the next point, the distance left and a sentence, from the forecourt, the lobby, the corridor, the office (round the clerk's desk), the other hall (by the aisles to its door) or the courtyard. The card (`ClassHud`) shows it only inside the university grounds.
* **Testing.** `scripts/test-academics.mjs` (about 80 checks, plain Node): the timetable's invariants and each day of Group B, no group ever double-booked, the attendance rules at their edges, a whole Monday attended lecture after lecture, both seats (fit, open on two sides, nobody else in the chair, the rest of the row still solid), the sitting pose (feet on the floor, hips on the seat, smooth blend), and a pilot that follows the guide with the real collision code from eight places to each seat and sits down on it, plus pressing the button from 56 places around the seats. `scripts/smoke-lectures.mjs` is the short browser check (menu chips, the timetable, the card, sitting through lectures with the clock, Hall 313, a Sunday); run it by hand (the "Browser test - lectures (manual)" workflow) or by putting `[lectures]` in a commit message on a branch.
* **Estimated, not measured.** The timetable is copied from the paper timetable the player sent. The halls' names are mapped onto the two estimated halls of Stage 8 (in reality Hall 313 is probably on the third floor, which is still a closed block); the end time of the Wednesday clinic block is approximate (the paper has no end for it).
* **Limits.** No questions or notes in a lecture (attendance only); no exams or assignments; the day does not advance (next day and sleep come in Stage 12); clinic and lab sessions are not playable; the sitting pose and the frame rate have not been seen on a real phone; the guide is hidden outside the university grounds.

## Dental clinic (Stage 10)

* **What it adds.** The large ground-floor hall of the university's west wing, entered by a 1.6 m double door at the west end of the corridor; twelve dental units, a hand-wash counter, a sterilising counter and a storage counter; the clinic sessions of the timetable as something she can attend; the three-step getting-ready routine before a session.
* **Layout (`uniLayout.ts`).** `CLINIC` is the south part of the wing's ground floor (15.2 m × 27 m between its walls); `CLINIC_WALLS` are three 0.4 m walls, the east one with the door opening; `CLINIC_BEHIND` is the rest of the wing, still a solid block, and `CLINIC_UPPER` the floors above (camera-only collider). The wing's own solid collider is replaced by walls, counters, chairs, trays and stools (`CLINIC_COLLIDERS`); a stool is solid unless somebody is seated on it or it is hers. `inClinic` joins the clinic and its 0.8 m passage and feeds `floorHeightAt`, `insideBuilding` and the place chip (`'clinic'`, "Dental clinic"). Her unit is the first row by the east aisle (`HER_UNIT`, `CLINIC_SEAT`); `CLINIC_PREP` holds the three places along the wash counter (wash, mask, gloves, from the door westwards).
* **Drawing (`buildCampus.ts`).** The wing's facade box stays (so nothing z-fights); only inner lining planes, the passage and the room's contents are drawn (`clinicShell`, `clinicRoom`, `dentalUnit`, `counter`). A sign over the door in the corridor and three small signs at the sink.
* **Rules (`academics/clinic.ts`, pure).** `PREP_STEPS` (wash, mask, gloves; seconds, game minutes, gesture), `completePrep` (an out-of-order step changes nothing), `prepPrompt` (greyed out with what to do first), `clinicSeatOffer` (the first clinic session she can still attend, enabled only when she is ready, with the late / too-late / wait notes of a lecture). The attendance rules are the lectures' own. `useClinicStore` holds the steps done; they reset after each session and on a new game; `?prep=done` skips them.
* **Wiring.** `world/campusInteraction.ts` adds four spots (the stool and the three prep places) to the seats of Stage 9: the same walk-to-the-spot-and-act loop. Three new gestures (`wash`, `mask`, `gloves`) in `animations/pose.ts` are arm movements only; the sit gesture is reused for the stool. `guideToClinic(x, z, target)` leads to the door and through the room (a flood-filled distance map inside, because the units leave winding aisles).
* **UI.** The class card guides to the next *session* (lecture or clinic), shows the three chips while she is in the clinic, and sends her to the next step. The timetable panel counts clinic sessions with the lectures; labs stay "Opens in a later stage".
* **Testing.** `scripts/test-clinic.mjs` (plain Node, about 50 checks): the room and its door, the units and counters (no overlaps, aisles of at least 1 m), the three spots, every free cell of the clinic reachable from the door and the rest of the wing unreachable, the getting-ready rules, what the stool offers across the week, a whole Tuesday session, and a pilot that follows `guideToClinic` with the real movement and interaction code from 13 places (the street, the lobby, the corridor, the office, a hall, the courtyard and all over the clinic) to each of the four spots. `scripts/smoke-clinic.mjs` is the short browser check (card, door, getting ready, a Tuesday session, Thursday's second session, a Monday), started by putting `[clinic]` in a commit message on a branch.
* **Estimated, not measured.** No photographs or plan of the real clinic: its size, the door, the units, the counters and the order of the three steps are estimates (the order can be changed in `PREP_STEPS`).
* **Limits.** No patients or cases (Stage 11); the lab sessions are still not playable; the mask and gloves are shown only on the card, not on the character; the sitting pose at the dental stool and the frame rate have not been seen on a real phone; the day does not advance.

## Checks on every push (since Stage 8)

* Every push to a branch, and every push to `main`, runs the quick checks: the Node tests (`npm test`) and `npm run build` (strict type-check and production build). A push to `main` then publishes the site. This takes a few minutes.
* The long browser walk-through (`scripts/smoke-test.mjs`, headless Chrome with software WebGL, about 25 minutes) no longer runs on every push. It is the "Browser test (manual)" workflow (`.github/workflows/browser-test.yml`): start it by hand from the Actions tab and pick the branch. The phone test by the player replaces it as the check of how a stage feels.
